# 定时任务

简体中文 | [English](README.en.md)

在常驻进程中运行秒级或分钟级任务。表达式使用内置稳定 `cron-expression 3.6.1`，无需额外安装；未使用时不加载解析器或创建计时器。

## 配置与调用

在已有 `config/process.php` 中增加进程，保留其他配置：

```php
'RC_Crontab_Task' => [
    'handler' => support\process\Crontab::class,
    'count' => 1,
],
```

进程类放在 `support/process/Crontab.php`：

```php
namespace support\process;

use RC\Helper\Crontab\Crontab as Task;

/** 在框架启动的任务进程中注册计划。 */
class Crontab
{
    /** 框架传入运行类型、Worker 和 Timer；业务方法无需自行初始化框架。 */
    public function __construct($type, $worker, $timer)
    {
        new Task('*/10 * * * * *', static function (): void {
            echo date('Y-m-d H:i:s'), PHP_EOL;
        }, $type, 'heartbeat');

        new Task('0 2 * * *', static function (): void {
            // 在这里调用项目已有的业务模型或公共方法。
        }, $type, 'daily-task');
    }
}
```

已有自定义进程也可在其启动阶段注册。不要在每次 HTTP 请求中反复创建任务，也不要在 fork 前的主进程中注册。直接使用 Workerman 时，放到 `onWorkerStart` 内。

## 表达式

**五段以“分钟”开头，六段以“秒”开头。** 不支持在末尾追加年份或 shell 命令。

```text
秒 分 时 日 月 星期    六段
   分 时 日 月 星期    五段，秒固定为 0
```

| 示例 | 含义 |
| --- | --- |
| `*/5 * * * * *` | 每 5 秒 |
| `*/5 * * * *` | 每 5 分钟 |
| `5-15/5 * * * * *` | 每分钟第 5、10、15 秒 |
| `5/10 * * * * *` | 每分钟从第 5 秒起，每隔 10 秒，直到第 55 秒 |
| `0 9 * * MON-FRI` | 工作日 09:00 |
| `0 0 L * *` | 每月最后一天 00:00 |
| `0 0 LW * *` | 每月最后一个工作日 00:00 |
| `0 0 1W * *` | 当月距离 1 日最近、且不跨月的工作日 |
| `0 0 * * FRI#2` | 每月第二个星期五 00:00 |
| `0 0 * * 5L` | 每月最后一个星期五 00:00 |
| `@hourly` / `@daily` | 每小时整点 / 每天 00:00 |

支持数字、列表、升序范围、正步长、`JAN-DEC`、`SUN-SAT`，周日可用 `0` 或 `7`。`?` 只可单独用于“日”或“星期”，不能两者同时使用；支持上游内置的小时/日/周/月/年宏，不读取进程全局自定义宏。`31W` 等目标日期当月不存在时不执行。

> 为兼容 RC 旧行为，“日”和“星期”都有限定时必须**同时满足**。例如 `0 0 1 * MON` 是“恰好为星期一的每月 1 日”，不是“每月 1 日或每个星期一”。

零步长、倒序范围、越界数字、不完整列表和未知语法会在注册时抛出异常，不会悄悄忽略条件。超大正步长只选取范围起点，不循环回绕。表达式最长 1024 字节。

## 取消与查询

```php
$task = new \RC\Helper\Crontab\Crontab('*/10 * * * * *', static function (): void {
    // 执行任务。
}, 'workerman', 'sync');

$id = $task->getId();
$name = $task->getName();
$all = \RC\Helper\Crontab\Crontab::getAll();
$removed = $task->destroy(); // 或 Crontab::remove($id) / remove($task)。
```

移除会取消自身待执行计时器，已从事件队列取出的旧回调也会检查注册状态；重复移除返回 false。最后一个任务移除后，共享的分钟计时器也会释放。名称仅用于标识，不自动去重；ID 只在当前进程内有效。

保留原来的 `($rule, $callback, $type, $name)` 参数；省略 type 默认 Workerman。显式 `type=null` 仅登记元数据，不启动，也不会被后来创建的其他引擎任务激活。不要克隆任务对象；需要另一个任务时重新构造。

## 时间与运行边界

- 使用任务进程的 `default_timezone`，未单独配置则沿用应用时区。不要在业务请求中临时改整个进程的时区。
- 分钟内新增任务只安排当前秒及以后的匹配点，不补执行注册前的秒。任务按真实 Unix 分钟登记，DST 回拨的两个同名本地分钟是两个时间点；系统时钟退回已安排的 Unix 分钟时不会重复安排它，大幅回拨期间可能暂停新排期，直到超过已安排分钟。单调计时器因回拨提前唤醒时会重新等待，不提前执行业务。
- 忙碌导致回调延迟时，本分钟的已到期匹配点可能连续执行；不会补跑完整跳过的旧分钟。不是硬实时或持久化调度，进程退出不会自动补偿漏跑。
- 普通 Workerman 回调仍在本进程执行。长时间阻塞会延迟其他任务；可按项目需要使用框架已有队列或独立进程。异常交给事件循环原有错误处理器，不吞掉异常，也不保证错误处理器终止进程后还能继续运行。
- 同一任务组设 `count=1` 可避免本机多个任务进程重复执行；多主机仍需业务幂等或合适的分布式协调。名称、ID、缓存表达式都不提供跨主机“只执行一次”。
- 每个任务最多保留一个待执行计时器，每个运行类型共享一个分钟计时器。`getAll()` 包含显式 dormant 登记。外部直接 `Timer::delAll()` 会破坏其他框架计时器，不是清理单个任务的方法。

Swoole 仅保留既有 Timer 桥接，没有新增协程支持；当前主线和真实事件循环验收以 Workerman 为准。

## 仅解析与打包

```php
$parser = new \RC\Helper\Crontab\Parser();
$valid = $parser->isValid('5-15/5 * * * * *');
$times = $parser->parse('5-15/5 * * * * *', 0, 'UTC'); // [5, 10, 15]
```

`parse()` 返回指定时间所在本地分钟的全部匹配时间戳，可能含该秒之前的值；**不是“寻找下一次运行时间”**。时间戳 0 不是当前时间。第三参数只指定本次解析时区，不改变进程时区；不创建任务或计时器。`isValid()` 检查语法与字段范围，不承诺“2 月 31 日”会出现。

运行源码和许可保留在框架包内，PHAR 可直接读取，不需向 exe 旁释放 PHP 源文件。兼容的外部 Composer 版本优先；当前只接受精确已测 `dragonmantank/cron-expression:3.6.1`，其他版本升级须重新检查适配。原 protected 解析/调度内部结构不是兼容接口，旧子类应复查；实现与验证范围见[迁移记录](../../../data/docs/crontab-migration.md)。
